# 论坛UI重设计方案

参考：https://meta.discourse.org/ （实际主题列表）；桌面左侧导航、中央列表/阅读区，移动端单列导航。沿用聊天现有字体和颜色体系，论坛采用白底、细分隔线、明确文字层级，不使用大面积圆角表单卡片。

## 页面拆分

1. 主题首页：左栏「所有主题、版块、草稿」，主栏搜索、版块筛选、新主题按钮及紧凑列表。列表只显示标题、版块、署名、真实存在的分支状态；不伪造浏览量、热度和时间。
2. 帖子详情：面包屑、标题、作者及正文、顺序回复。正文优先；历史/对照、举报、管理动作放每帖更多菜单。正文副本说明按需展开。
3. 发布/编辑：独立编辑视图，返回来源页面；标题、正文、附件、发布/保存草稿，不与主题列表混排。未提交输入在导航时保留。
4. 网络连接：独立页面，显示在线状态、连接节点和复制当前入口。首页仅保留简短连接状态入口。
5. 管理后台：管理员专属入口，分成员、版块、举报三页；历史检查点置于管理操作，不进入普通读帖页面。
6. 首次加入：先选加入已有论坛或创建论坛，再显示对应表单；公开身份按申请步骤展示。

## 布局与交互

- 桌面约200px左栏，主内容最大960px，正文最大760px；手机隐藏侧栏，改紧凑导航，触控区至少48px。
- 主题列表和帖子详情使用同一论坛顶栏；论坛内不重复展示整套聊天大标题。
- 普通状态不用常驻大横幅；错误保留明确的重试入口。管理表单不出现在普通主题浏览中。
- 保留现有DOM入口与受限原生接口，重构前端导航及排版，不修改签名、准入或文件协议。

## 实施与验收

先完成前端页面与导航，再适配主题/草稿/连接/管理操作及恢复，最后更新替身测试并做原生实际截图。覆盖桌面1000px、手机320/390px，返回路径、取消编辑、草稿恢复、权限可见性、锁定清理及已有聊天回归。真实原生截图用于验收，不以布局测试代替视觉检查。
