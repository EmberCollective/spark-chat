What this repo does: Spark Chat 在校园网内连接两位用户，交换加密消息和文件，并加密保存文字记录。审查按两人日常聊天、数千条文字、少量附件估算负载；不包含 mTLS 门户或教学实验区。

审查口径：先对原 egui 源码只读审查，随后用户批准现代客户端实现。下方同时记录原有问题与迁移期间发现的问题；“已修复”不等于正式安全认证。原版行号指 .agents/backups/egui-baseline-20261025.tar.gz 中的文件。

Must fix — 正式发布前仍需处理的旧问题

1. 同一会话密钥下，重开会话的随机前缀只有 32 位（src/vault.rs:357–379）。
   用途：为每条落盘密文生成不能重复的 nonce，可理解为同一把钥匙下不能重复的流水号。
   问题：每次 open_session 重新随机 4 字节，后 8 字节计数又从零开始；前缀碰撞会重复使用同一密钥与 nonce。约 9300 次重开时，发生至少一次前缀碰撞的概率约 1%。未人为制造碰撞。
   最小处理：单独设计并审核持久化唯一计数或成熟的带独立随机文件密钥的存储格式，保留旧记录读取；本轮不改加密文件格式。
   不处理后果：长期反复重连时，落盘加密可能失去应有保护，不能据此声明正式安全可用。
   依据：https://docs.rs/chacha20poly1305/0.10.1/chacha20poly1305/ 。

2. 会话接受全零 X25519 公钥（src/vault.rs:340–355）。
   用途：用对方公钥和本机私钥派生存储密钥。
   问题：隔离探针确认 register_peer("peer", &[0;32]) 后 open_session 仍成功；此类输入可能得到公开可预测的共享值。
   最小处理：使用已有 x25519-dalek 的 was_contributory() 验证结果并拒绝失败；补安全回归测试。留待独立密码学边界修复。
   不处理后果：面对异常或恶意公钥，不能保证派生密钥仍包含双方秘密。
   依据：https://docs.rs/x25519-dalek/latest/src/x25519_dalek/x25519.rs.html 。

Should fix — 旧接口剩余问题

3. Vault::create 公共接口会覆盖已有钥匙文件（原 src/vault.rs:197–199）。
   用途：第一次生成第二把钥匙。
   问题：隔离探针在指定路径先写入原内容，create 后该内容被替换。新客户端 authenticate 已拒绝选中现有文件，但底层接口本身仍缺原子防覆盖。
   最小处理：底层使用 create_new 打开新文件；同时测试现有内容保持不变。
   不处理后果：其他调用者或并发创建仍可能破坏已有钥匙。普通新 GUI 路径已有前置保护。

Must fix — 本轮已修复并回归的功能问题

4. 部分连接码无法原样解开（原 src/protocol.rs:70–86；已修复）。
   用途：把地址与公开身份交给对方。
   问题：base64url 本身包含短横线，旧解析器却删除所有短横线；确定性 salt=62 的往返探针即可复现。
   最小处理：新码不插分隔符；先解析原文，再按固定位置兼容旧分组格式，保留真正的数据短横线。
   不处理后果：用户即使整段复制，也会随机遇到连接失败。

5. 保存失败仍显示成功，而且丢掉唯一缓存（原 src/app.rs:127–131、src/ui.rs:618–621；已修复）。
   用途：把收到的附件保存到用户指定位置。
   问题：写文件前先移除缓存，失败只打日志；UI 随即显示“已保存”。隔离失败路径已复现。
   最小处理：写入成功后才移除缓存并反馈成功；失败保留数据和重试入口。
   不处理后果：用户误以为文件已保存，实际无法再取回。

6. 磁盘历史没有进入真实聊天页面（原 src/app.rs:150–164、src/ui.rs:536–540；已修复）。
   用途：连接后恢复已有记录。
   问题：UI 仅在解锁时取一次空缓存，后台之后加载历史却没有发刷新事件；真实路径还把完整身份缩成末 8 位。
   最小处理：后台使用完整身份，加载完成后发 History 和 SessionReady；旧末 8 位路径仅在公钥匹配时复制迁移，原件保留。
   不处理后果：用户看不到已有记录，或误以为记录消失。

7. 历史消息把毫秒当秒显示（原 src/app.rs:108–110、src/ui.rs:1540；已修复）。
   用途：显示消息时间。
   问题：真实后端存毫秒，旧 UI 格式化函数按秒解释；隔离探针确认缓存时间大于 10^12。
   最小处理：页面统一把后端时间作为毫秒，使用本地日期与时间格式显示。
   不处理后果：恢复后的日期不正确。

8. 锁定只遮住界面，重新解锁又开一条网络线程（原 src/ui.rs:544–548、src/app.rs:84–90；已修复）。
   用途：离开电脑时锁住聊天。
   问题：旧网络和明文一直留在后台；再次解锁会替换通道，旧连接与 UI 状态分开。
   最小处理：锁定停止网络并释放会话、消息、附件缓存；有未保存或未完成附件时先提醒用户。
   不处理后果：锁屏含义不清，重开后可能出现残留连接或附件丢失。

9. 第三个连接会覆盖当前对方（原 src/net.rs:279–286、312–315；已修复）。
   用途：维护当前一对一聊天对象。
   问题：新连接直接替换 peer，旧连接仍可送入不带来源的消息事件；回复可能发给另一人。
   最小处理：当前一对一会话拒绝其他身份连接，接收帧时核对当前对方。
   不处理后果：消息可能进入错误会话，回复也可能发错人。

10. 特制公钥文本可使网络线程崩溃（原 src/net.rs:352–356、419–422；已修复）。
    用途：解析握手里的十六进制公钥。
    问题：64 字节不等于 64 个 ASCII 字符；例如包含多字节汉字或其他 Unicode 时，旧字符串切片可能切到字符中间。
    最小处理：先验证 ASCII 和偶数长度，再解析；新增不崩溃测试。
    不处理后果：异常对端可以中断聊天服务。

11. 分块文件依赖未保证的到达顺序，空文件没有完成路径（原 src/net.rs:258–268、364–390；已修复）。
    用途：接收文件元数据和内容。
    问题：元数据与分块各走独立请求，接收端却直接追加且忽略序号；空文件则没有任何分块触发完成。
    最小处理：发送方收到前一块响应再发下一块，接收端核对序号和长度，单独处理空文件。
    不处理后果：普通文件可能丢块或校验失败，空文件一直停在接收中。

12. 双向编号混用，以及对方重启后编号重复（原 src/ui.rs:418–445、src/app.rs:190–191；已修复）。
    用途：关联附件气泡、进度与保存动作。
    问题：收发都可能从 1 编号；同一对方重启后再次发送 1，旧文件名可能对应新内容。
    最小处理：页面区分收发；接收端生成独立的本机保存编号，线上编号只做当前接收任务映射。测试同一线上编号的两个文件可分别原样保存。
    不处理后果：保存错内容，或进度落到另一份文件上。

13. 附件接收和未保存缓存缺少总量限制（原 src/net.rs:365–371、src/app.rs:190–191；已修复）。
    用途：在用户保存前暂存附件。
    问题：元数据可反复申请大内存，缓存也只增不减。
    最小处理：单文件 64 MiB、最多两份接收中；未保存缓存最多 32 项、合计 128 MiB；空间不足时明确拒绝并引导先保存。
    不处理后果：大量附件可能耗尽内存。

14. 连续文字可能乱序（原 src/net.rs:235–239；已修复）。
    用途：把连续输入的消息按顺序发出去。
    问题：真实 Mac 窗口中两条欢迎语顺序反了；独立请求没有保证先后顺序。
    最小处理：文字使用有上限的等待队列，等前一条响应后发送下一条，文件仍独立传输。
    不处理后果：对话顺序与发送顺序不一致。已用双向各 24 条文字并发文件测试验证。

15. 默认空闲期限使聊天很快断开（原 src/net.rs Swarm 构造；已修复）。
    用途：保留已建立的聊天连接。
    问题：实际窗口停顿后收到 expired keep-alive timeout；原代码沿用库的短空闲期限。
    最小处理：显式设置 24 小时空闲期限；真实两节点测试闲置 12 秒后继续发消息，Mac 实际窗口也验证了更长停顿后发送与传文件。
    不处理后果：用户正常停顿也会被迫重新连接。

Should fix — 迁移时发现并修复

16. 重新载入文字历史会移除未保存附件（web/app.js replaceHistory；已修复）。
    用途：重连后刷新记录。
    问题：页面清空文件卡片，但 Rust 仍保留文件数据。
    最小处理：同一对方的附件卡片按原时间保留；上一位还有附件待保存时，拒绝直接切到另一位。
    不处理后果：附件仍在内存，却找不到保存入口。

17. 声明支持的旧版 WebKit 没有 requestSubmit（web/app.js 回车处理；已修复）。
    用途：按回车发送。
    问题：直接调用较新的表单方法会在旧系统报错。
    最小处理：触发现有发送按钮；保留输入法确认回车和 Shift+Enter 的判断。
    不处理后果：旧系统只能鼠标发送。浏览器替身检查已模拟缺失该方法；旧 macOS 设备尚未实测。
    依据：https://developer.apple.com/documentation/safari-release-notes/safari-16-release-notes 。

18. 记住路径失败会阻止本来有效的解锁（src/app.rs authenticate；已修复）。
    用途：下次启动时预填钥匙文件位置。
    问题：偏好文件单独不可写，也会让已成功解锁的库变成登录失败。
    最小处理：继续解锁并发提醒；新增偏好路径不可写的回归测试。
    不处理后果：小配置错误阻止聊天。

验证：最初的 16 个库测试和文字互通测试通过，但不能覆盖上述全部问题。另有 7 项只读隔离探针证实边界问题；最终 21 个库测试、11 个集成层测试、1 个真实双节点综合测试，以及 14 项浏览器界面检查通过。实际 Mac 窗口完成解锁、真实连接、多行中文、附件双向发送与保存、字节校验、锁定和重新解锁。

Verdict: 现代 UI 与已测聊天流程可作为 Mac 本地预览交付；1–3 项旧密码学/底层文件接口问题留待独立修复，不能当成正式安全验收通过。
Not checked: Windows/Linux 实机、旧版 macOS、跨宿舍网络、正式下载分发与 Apple 公证、断电恢复、长期高负载、原生 GitHub Code Review/Security Review。当前目录没有 Git 仓库或远程 PR。
