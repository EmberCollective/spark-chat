# 论坛与多会话架构草案（2026-11-09）

状态：历史草案；以《实施计划书-校园论坛与多会话-V1-20261109.md》为当前待审批依据，尤其以其中人人署名编辑、分区合并规则为准。仅整理设计，未实现、未安全验收。

## 已确认方向

- 保留 spark-chat 双端加密聊天和既有历史、文件功能；一个客户端可同时连接多个节点、保持多个独立一对一会话。
- 论坛与聊天入口分离：不从论坛作者、帖子或公钥直接发起聊天，不用论坛连接自动建立私聊。
- 论坛采用完整轻量索引、签名增量记录、按需下载的内容对象；管理员离线仍可发帖、回复和同步。
- 成员由邀请和管理者批准准入；资格与撤销由各节点验证。撤销传播有延迟，不追回已下载内容。
- 校园断电后地址可能全变。第一版人工导入当前入口，缓存重连为辅助；DNS 自动发现后续研究。不扫描全校 IP，不依赖唯一在线论坛主机。
- 支持输入框粘贴图片（Windows/Linux Ctrl+V、macOS Cmd+V）；粘贴后预览待发送内容，明确发送才上传。
- 聊天内直接显示已校验图片，可另行保存原图；无需先导出到用户目录。普通文件仍走明确的选择保存流程。

## 身份、来源与隐私边界

作者签名证明某密钥持有者授权了一次变更；内容哈希用于完整性校验。内容来源身份与当前提供副本的节点不是同一概念。

论坛对象和索引不写入上传 IP、设备主机名、网卡标识；不建立面向成员的作者查 IP 接口。副本从 B 下载，不说明 B 是作者。

但这不是匿名上传：直接接收上传的节点可同时观察连接 IP、认证身份及签名对象。即使产品不记录，恶意节点也可记录；首次传播与流量关联仍可能暴露作者。不得宣称仅凭公钥签名就无法追溯 IP。聊天直连双方知道彼此 IP。

## 模块与协议

1. 身份与资格：本机私钥库、邀请证明、签名管理记录；论坛资格不自动授予私聊关系。
2. 连接与会话：多个连接独立管理；网络命令和事件明确目标/来源及会话代次。论坛邻居与聊天会话逻辑隔离。
3. 论坛对象：规范化编码，签名绑定协议用途、网络、作者、操作、引用、正文哈希及附件元数据；编辑追加新对象，不覆盖旧对象。冲突分支保留，不按时间静默裁决。
4. 论坛索引：全员同步轻量元数据及验证依据。快照用于启动加速，不能替代权限与签名验证；上线对比并补齐增量。
5. 对象存储：正文与附件按哈希寻址，下载完整验证后才宣告可提供；索引可见不代表副本当前可达。
6. 副本发现：本地优先，有限邻居查询、去重、超时、限频；提供者短期缓存。无结果表示本轮未找到，不表示全网不存在。
7. 界面：论坛参考 Discourse 主题列表、顺序回复与编辑器；聊天延续 Telegram Desktop/Android。中文系统字体，手机单列、48px 触控目标、软键盘与安全区适配。

线上共享类型继续集中在 protocol.rs。现有聊天帧及 AppHooks 方法签名不得擅改；新增能力通过经批准的新增接口/版本协议承载，旧客户端能力不足时明确降级。论坛和图片扩展先约定版本协商，不将旧 FileMeta 悄悄解释为可自动接收图片。

## 多会话隔离

消息、附件进度、传输编号、接收目标、历史和草稿均明确所属会话；不能依赖 UI 当前选中的联系人路由异步结果。使用会话身份、连接代次、方向及传输编号避免碰撞和重连旧事件污染。

切换会话不切断其他连接；单个对端离线不清空其他会话。锁定停止所有业务连接，释放解密材料和明文预览，并保留应加密保存的数据。论坛收到的签名对象不能进入私聊消息流。

## 图片粘贴与内联预览

- 仅处理用户触发的粘贴事件，不后台读取剪贴板；纯文字粘贴维持原行为。
- 粘贴后展示待发送缩略图，允许取消和文字说明；发送时绑定会话，切换联系人不得误发。
- 图片类型依据实际内容检测，限制压缩字节数、解码像素及内存；第一版优先静态 PNG/JPEG/WebP，不内联执行 SVG/HTML。
- 预览数据由原生层校验并通过受控资源标识交给页面；不开放任意文件路径，密钥不进入页面。
- 小图接收后直接预览；超限图片降级为文件或明确提示，不无限自动下载。具体自动接收阈值待实施前确认，建议 5 MB、单图 20 百万像素以内。
- 使用受限内存或加密应用缓存，不创建无控制明文临时副本；锁定清除明文视图。应用自有缓存属于本次新增授权范围，不替代普通文件的用户选址。
- Android 页面/Activity 重建恢复预览入口与会话归属；真正杀进程后的恢复另行实现和验收，不混淆。

## 论坛资源默认值（建议，非现有聊天全局限制）

- 单附件 20 MB，每次发布最多 5 个附件、合计 30 MB。
- 图片默认缩略图，原文件按需获取；链接不自动抓取外部预览，不加载外链图片。
- 桌面普通内容缓存初始 1 GB；自身发布和主动保留内容独立管理，不能静默清除唯一已知副本。
- 后台内容分发总上行初始 5 Mbps，前台聊天优先；并发与排队有总量限制。
- 发布区分本机保存、已被其他节点确认、附件副本状态；尝试取得至少一个外部完整副本，不虚构永久可用性。
- 每个查询、上传、下载和管理入口都验证资格、访问权限、长度与配额；知道哈希不是下载授权。

## 现有源码影响范围

已核对 net.rs 只有一个 peer 状态，NetCmd/NetEvent 多数不带会话来源；web/app.js 有单一 peer 和全局附件表。不是增加一个连接按钮即可完成。

预期涉及 src/net.rs、app.rs、protocol.rs、ui.rs、desktop.rs、transfer.rs、web/；图片原生 I/O 如需 Android 接口扩展再触及 src/android.rs 和维护中的 Android 工程。vault.rs 仅在必要的安全修复、缓存加密及兼容迁移中调整，禁止覆盖旧库或钥匙。

现有调用者、测试、界面恢复快照和测试替身必须同步适配；配置仅添加实际使用的能力。不启用 STUN/relay 或公网发现。

## 实施批次与验收

1. 安全与协议前置：复核已记录 vault 风险，约定会话标识和能力协商；测试旧格式可读且失败不破坏旧数据。
2. 多会话：三节点双向同时发消息和文件；验证编号重复、切换会话、单端断开、重连及锁定均不串数据。
3. 图片聊天：粘贴、取消、发送、内联预览、保存；验证普通文本、超限/伪装图片、断网、旧客户端和页面重建。
4. 论坛准入与对象：邀请批准、签名对象、主题/回复、增量索引、有限查询；验证伪造签名、重放、跨论坛对象与权限绕过。
5. 附件缓存与 UI：完整论坛界面、大小限制、后台限速、草稿和缺副本状态；验证管理员离线、作者离线、网络分区再合并。
6. 交付：构建、实际安装包运行、跨端通信、用户验收分别记录；产物绑定源码与哈希，Windows/实体 Android 未测就标未测。

每批拆成独立可回滚的小改动，依赖顺序执行；不自动合主或发布。当前仅准备架构，未启动实现或委派。
